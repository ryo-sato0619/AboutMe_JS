### PnP.PowerShell v1.1.2での監査ログ取得方法

PnP.PowerShell v1.1.2 では、統合監査ログ (`Search-UnifiedAuditLog`) を直接呼び出す専用のコマンドレットは提供されていません。そのため、Microsoft Purview の監査ログを取得するには、**Exchange Online PowerShell (v2モジュール)** を使用する必要があります。これはPnP.PowerShellとは別のモジュールですが、監査ログの取得にはこちらを利用するのが標準的な方法です。

PnP.PowerShellは、主にSharePoint OnlineやMicrosoft Teamsなどの構成管理に特化しており、監査ログの取得はMicrosoft 365のコンプライアンスセンターが提供する基盤（Unified Audit Log）から直接行う形になります。

-----

#### 前提条件: Exchange Online PowerShell v2 モジュールへの接続

監査ログを取得する前に、Exchange Online PowerShell v2 モジュールに接続してください。

1.  **Exchange Online PowerShell v2 モジュールのインストール (まだの場合)**
    管理者としてPowerShellを開き、以下のコマンドを実行します。

    ```powersell
    Install-Module -Name ExchangeOnlineManagement
    ```

2.  **Exchange Online PowerShell への接続**
    以下のコマンドを実行し、Microsoft 365 の管理者アカウントでサインインします。

    ```powershell
    Connect-ExchangeOnline
    # 多要素認証 (MFA) が有効な場合は Connect-ExchangeOnline -UserPrincipalName your.admin.account@yourdomain.com
    ```

    これにより、監査ログの取得に必要な `Search-UnifiedAuditLog` コマンドレットが利用可能になります。

#### 監査ログの取得パターン

##### 1\. URLと期間を指定して監査ログを取得する

特定のSharePointサイトのURLに関連する活動を期間指定で取得するには、`Search-UnifiedAuditLog` でログを取得した後、PowerShellの `Where-Object` を使って**監査データのJSON文字列内にあるURL**をフィルターします。

```powershell
# 期間を指定 (例: 2025年7月1日から7月14日まで)
$startDate = Get-Date -Date "2025-07-01T00:00:00Z"
$endDate = Get-Date -Date "2025-07-14T23:59:59Z"

# 検索したいSharePointサイトのベースURL (例: "https://yourtenant.sharepoint.com/sites/YourSiteName")
$targetSharePointBaseUrl = "https://yourtenant.sharepoint.com/sites/MyProject"

# 監査ログを検索
# SharePoint関連の操作に絞り込むため、WorkloadsとOperationsを指定します。
# PnP.PowerShell 1.1.2 の環境であっても、この部分は Exchange Online PowerShell の機能です。
$auditLogs = Search-UnifiedAuditLog -StartDate $startDate -EndDate $endDate `
    -Workloads "SharePoint" `
    -Operations "FileAccessed", "FileDownloaded", "FileUploaded", "FileDeleted", "PageView", "SharingSet" `
    -ResultSize Unlimited # Unlimited は多くのログを取得する場合に必要ですが、時間がかかります

# 取得したログから、AuditData の JSON 内にある SiteUrl でフィルターします。
# AuditData は JSON 文字列なので、Contains で部分一致を検索します。
$filteredLogs = $auditLogs | Where-Object { $_.AuditData -like "*\"SiteUrl\":\"*$($targetSharePointBaseUrl)*\"*" }

# 結果の表示例 (必要に応じて詳細プロパティを指定してください)
$filteredLogs | Select-Object CreationDate, UserIds, Operations, Workload, @{Name='SiteUrl'; Expression={($_.AuditData | ConvertFrom-Json).SiteUrl}} | Format-Table

# 必要に応じて CSV にエクスポート
# $filteredLogs | Export-Csv -Path "C:\temp\SharePointAuditLog_URL.csv" -NoTypeInformation -Encoding UTF8
```

**重要な注意点**:

  * `AuditData` はJSON形式の文字列として返されるため、その中の特定のプロパティ（例: `SiteUrl`）でフィルターするには、`Where-Object { $_.AuditData -like "*\"SiteUrl\":\"*$($targetSharePointBaseUrl)*\"*" }` のように**文字列としてパターンマッチング**を行う必要があります。`ConvertFrom-Json` を挟むと処理が重くなるため、まずは文字列検索で絞り込み、その後で `Select-Object` 内で `ConvertFrom-Json` を使用して整形するのが効率的です。
  * `Workloads "SharePoint"` と `Operations` パラメータで、関連するアクティビティを絞り込むことが重要です。

##### 2\. Yammerと期間を指定して監査ログを取得する

Yammer (現在の Viva Engage) の監査ログを期間指定で取得するには、`Search-UnifiedAuditLog` の `Workloads` パラメータで `"Yammer"` を指定します。

```powershell
# 期間を指定 (例: 2025年7月1日から7月14日まで)
$startDate = Get-Date -Date "2025-07-01T00:00:00Z"
$endDate = Get-Date -Date "2025-07-14T23:59:59Z"

# Yammer の監査ログを検索
# Yammer 関連の操作をさらに絞り込みたい場合は、Operations パラメータも併用します。
# 例: "MessagePosted", "PostCreated", "MessageReplied", "GroupJoined" など
$yammerLogs = Search-UnifiedAuditLog -StartDate $startDate -EndDate $endDate `
    -Workloads "Yammer" `
    -ResultSize Unlimited

# 結果の表示例
$yammerLogs | Select-Object CreationDate, UserIds, Operations, Workload, @{Name='ObjectId'; Expression={($_.AuditData | ConvertFrom-Json).ObjectId}}, @{Name='OperationName'; Expression={($_.AuditData | ConvertFrom-Json).OperationName}} | Format-Table

# 必要に応じて CSV にエクスポート
# $yammerLogs | Export-Csv -Path "C:\temp\YammerAuditLog.csv" -NoTypeInformation -Encoding UTF8
```

Power Apps で TextInput の情報を SharePoint や Microsoft Lists のリストに格納し、さらに TextInput がデフォルト値や空白の場合にエラーを出す方法ですね。承知いたしました。

これを実現するには、主に以下の関数とロジックを使用します。

  * **`Patch` 関数**: SharePoint/Lists に新しいアイテムを作成したり、既存のアイテムを更新したりするために使います。
  * **`IsBlank` 関数**: TextInput が空白かどうかをチェックするために使います。
  * **`Notify` 関数**: エラーメッセージや成功メッセージをユーザーに表示するために使います。
  * **`If` 関数**: 条件分岐（TextInputが空白/デフォルト値かどうかのチェック）を行うために使います。

以下に具体的な設定手順と例文を示します。

-----

### 1\. SharePoint / Microsoft Lists の準備

まず、データを格納するためのリストが必要です。

  * SharePoint サイトまたは Microsoft Lists に新しいリストを作成します。
  * 例えば、以下のような列（カラム）を作成します。
      * **タイトル** (既定で存在する列) - シングルテキスト行
      * **アクセス数** (数値) - 数値列
      * **備考** (複数行テキスト) - 複数行テキスト列

### 2\. Power Apps アプリの準備

1.  **データソースの追加:**

      * Power Apps Studio で、左側のナビゲーションから「データ」アイコン（円柱のようなアイコン）をクリックします。
      * 「データの追加」をクリックし、「SharePoint」または「Microsoft Lists」を選択します。
      * 接続したいサイトを選択し、作成したリスト（例: `MyDataList`）を選択して「接続」をクリックします。

2.  **コントロールの配置:**

      * 画面に、データを入力するための **TextInput** コントロールを配置します。
          * 例:
              * `TextInput_Title` (タイトル入力用)
              * `TextInput_AccessCount` (アクセス数入力用)
              * `TextInput_Notes` (備考入力用)
      * データをリストに保存するための **Button** コントロールを配置します。（例: `Button_Submit`）

### 3\. TextInput のデフォルト値とエラーチェック

TextInput がデフォルト値や空白の場合にエラーを出すロジックを、ボタンの `OnSelect` プロパティに記述します。

#### 例文: `Button_Submit` の `OnSelect` プロパティ

以下のコードを、`Button_Submit` コントロールの `OnSelect` プロパティに設定してください。

```powerapps
// (1) 入力値のバリデーション（検証）
// TextInput_Title が空白、またはデフォルトの "Text input" のままの場合
If(
    IsBlank(TextInput_Title.Text) || TextInput_Title.Text = "Text input",
    Notify("タイトルを入力してください。", NotificationType.Error), // エラーメッセージを表示
    
    // TextInput_AccessCount が空白、またはデフォルトの "Text input" のままの場合
    IsBlank(TextInput_AccessCount.Text) || TextInput_AccessCount.Text = "Text input",
    Notify("アクセス数を入力してください。", NotificationType.Error),
    
    // (2) バリデーションが全てOKだった場合のみ、SharePointリストにデータを格納
    // Patch関数を使って新しいアイテムを作成します。
    Patch(
        MyDataList, // 接続したSharePointリストの名前
        Defaults(MyDataList), // 新しいアイテムを作成することを示す
        {
            // リストの列名: TextInputのTextプロパティ
            Title: TextInput_Title.Text, // タイトル列にTextInput_Titleの値を格納
            AccessCount: Value(TextInput_AccessCount.Text), // アクセス数列にTextInput_AccessCountの値を数値に変換して格納
            Notes: TextInput_Notes.Text // 備考列にTextInput_Notesの値を格納
        }
    );
    
    // データ格納後の処理（例: 成功メッセージ表示、入力値のリセット、画面遷移）
    Notify("データが正常に保存されました。", NotificationType.Success); // 成功メッセージを表示
    Reset(TextInput_Title); // TextInput_Title をデフォルト値に戻す
    Reset(TextInput_AccessCount); // TextInput_AccessCount をデフォルト値に戻す
    Reset(TextInput_Notes); // TextInput_Notes をデフォルト値に戻す
    // Navigate(ScreenSuccess, ScreenTransition.Fade); // 成功画面に遷移したい場合
)
```

### コードの解説

1.  **`If(...)` 関数:**

      * `If` 関数は、複数の条件を順番に評価し、最初に `true` になった条件に対応する処理を実行します。
      * `If(条件1, 処理1, 条件2, 処理2, ..., 最後の処理)` の形式で使っています。
      * もし `条件1` が `true` なら `処理1` を実行し、そこで `If` 関数は終了します。
      * `条件1` が `false` なら `条件2` を評価し、`true` なら `処理2` を実行します。
      * 全ての条件が `false` だった場合、最後の処理（この場合は `Patch` 関数とそれに続く成功処理）が実行されます。

2.  **`IsBlank(TextInput_Title.Text)`:**

      * `IsBlank()` 関数は、指定された値が空白（空の文字列、null、または未定義）である場合に `true` を返します。
      * `TextInput_Title.Text` は、`TextInput_Title` コントロールに入力されているテキストの値を取得します。

3.  **`TextInput_Title.Text = "Text input"`:**

      * これは、TextInput コントロールの**初期のプレースホルダーテキスト**がそのまま残っているかをチェックしています。
      * Power AppsのTextInputコントロールは、デフォルトで「Text input」というプレースホルダーが表示されるため、ユーザーが何も入力せずにそのまま残している場合にこれを検知できます。
      * もし、TextInputの `HintText` プロパティを自分で「タイトルを入力」などに変更している場合は、その変更後のテキストと比較するように修正してください。
          * 例: `TextInput_Title.Text = "タイトルを入力"`

4.  **`Notify("メッセージ", NotificationType.種類)`:**

      * 画面の上部に一時的に通知メッセージを表示します。
      * `NotificationType.Error`: 赤色のエラーメッセージ。
      * `NotificationType.Warning`: 黄色の警告メッセージ。
      * `NotificationType.Success`: 緑色の成功メッセージ。
      * `NotificationType.Information`: 青色の情報メッセージ。

5.  **`Patch(MyDataList, Defaults(MyDataList), { ... })`:**

      * `Patch` 関数は、データソース（`MyDataList`）に対してデータを変更（追加または更新）します。
      * `Defaults(MyDataList)`: これを指定することで、`MyDataList` に**新しい行（アイテム）を追加する**ことを指示します。
      * `{ Title: TextInput_Title.Text, ... }`: 波括弧 `{}` の中に、リストの列名と、そこに入力したいコントロールの値をペアで記述します。
          * `Title`: SharePointリストの「タイトル」列です。
          * `AccessCount`: SharePointリストの「アクセス数」列です。
          * `Value(TextInput_AccessCount.Text)`: `TextInput` から取得される値は常にテキストなので、数値列に格納する場合は `Value()` 関数を使って**数値に変換する**必要があります。変換できない場合はエラーになるので注意してください。
          * `Notes`: SharePointリストの「備考」列です。

6.  **`Reset(TextInput_Title)`:**

      * `Reset()` 関数は、指定されたコントロールをその初期状態（`Default` プロパティの値）に戻します。これにより、データ保存後にTextInputの入力内容をクリアできます。

この設定で、ユーザーが必須項目を適切に入力しない限りデータを保存せず、エラーメッセージを表示する堅牢なアプリを作成できます。

## メールアドレス形式のチェックと入力なしの区別

メールアドレスの形式チェックには、`IsMatch` 関数を使うのが最も強力で正確です。`IsMatch` は、入力されたテキストが特定のパターン（正規表現というルール）に合っているかをチェックできます。

### 前提

  * メールアドレス入力用の `TextInput` コントロールがあること。（例: `TextInput_Email`）
  * 受け付けたいドメイン（例: `@example.com` や `@yourcompany.co.jp` など）が決まっていること。

### 例文: `Button_Submit` の `OnSelect` プロパティ

以下のコードを、あなたの `Button_Submit` コントロールの `OnSelect` プロパティに組み込んでください。

```powerapps
// (1) 入力値のバリデーション（検証）

// TextInput_Title のバリデーション
If(
    IsBlank(TextInput_Title.Text) || TextInput_Title.Text = "Text input",
    Notify("タイトルを入力してください。", NotificationType.Error),
    
    // TextInput_AccessCount のバリデーション
    IsBlank(TextInput_AccessCount.Text) || TextInput_AccessCount.Text = "Text input",
    Notify("アクセス数を入力してください。", NotificationType.Error),
    
    // ドロップダウンのバリデーション
    IsBlank(
        LookUp(
            Table(
                { DisplayText: "選択してください", Value: Blank() },
                { DisplayText: "公開", Value: 1 },
                { DisplayText: "非公開", Value: 2 },
                { DisplayText: "一部公開", Value: 3 }
            ),
            DisplayText = Dropdown_Privacy.Selected
        ).Value
    ), 
    Notify("公開設定を選択してください。", NotificationType.Error),

    // --- ここからメールアドレスのバリデーション ---
    // TextInput_Email が空白かどうかをチェック
    IsBlank(TextInput_Email.Text),
    Notify("メールアドレスを入力してください。", NotificationType.Error), // 空白の場合のメッセージ
    
    // TextInput_Email が特定のドメイン形式に合致するかどうかをチェック
    // '@example.com' と '@yourcompany.co.jp' の両方を許可する場合の例
    !IsMatch(
        TextInput_Email.Text,
        // 正規表現: アルファベット、数字、記号（. % + - _）の後に @ が来て、
        // その後に 'example.com' または 'yourcompany.co.jp' で終わる
        // i は大文字小文字を区別しないことを意味します
        "^[a-zA-Z0-9.!#$%&'*+/=?^_`{|}~-]+@(?:example.com|yourcompany.co.jp)$",
        MatchOptions.IgnoreCase // ドメイン名の大文字・小文字を区別しない
    ),
    Notify("有効なメールアドレス（@example.com または @yourcompany.co.jp ドメイン）を入力してください。", NotificationType.Error), // 形式が違う場合のメッセージ
    // --- メールアドレスのバリデーションここまで ---
    
    // (2) バリデーションが全てOKだった場合のみ、SharePointリストにデータを格納
    Patch(
        MyDataList,
        Defaults(MyDataList),
        {
            Title: TextInput_Title.Text,
            AccessCount: Value(TextInput_AccessCount.Text),
            Notes: TextInput_Notes.Text,
            PrivacySetting: LookUp(
                Table(
                    { DisplayText: "選択してください", Value: Blank() },
                    { DisplayText: "公開", Value: 1 },
                    { DisplayText: "非公開", Value: 2 },
                    { DisplayText: "一部公開", Value: 3 }
                ),
                DisplayText = Dropdown_Privacy.Selected
            ).Value,
            EmailAddress: TextInput_Email.Text // SharePointリストにメールアドレス列を追加していると仮定
        }
    );
    
    // データ格納後の処理
    Notify("データが正常に保存されました。", NotificationType.Success);
    Reset(TextInput_Title);
    Reset(TextInput_AccessCount);
    Reset(TextInput_Notes);
    Reset(Dropdown_Privacy);
    Reset(TextInput_Email); // メールアドレスもリセット
    // Navigate(ScreenSuccess, ScreenTransition.Fade);
)
```

-----

### コードの解説

1.  **`IsBlank(TextInput_Email.Text)`**

      * これは、メールアドレスの入力欄(`TextInput_Email`)が**完全に空っぽ**であるかをチェックします。
      * `true` の場合、「メールアドレスを入力してください。」というエラーメッセージを表示します。

2.  **`!IsMatch(TextInput_Email.Text, "...", MatchOptions.IgnoreCase)`**

      * `IsMatch()` 関数は、最初の引数（`TextInput_Email.Text`）が、2番目の引数で指定された**正規表現パターン**に合致するかどうかをチェックします。
      * `!` (感嘆符) は「ではない」という意味で、パターンに**合致しない場合**に `true` になります。つまり、形式が正しくない場合にエラーを出します。
      * **正規表現パターン (`"^[a-zA-Z0-9.!#$%&'*+/=?^_`{|}\~-]+@(?:example.com|yourcompany.co.jp)$"\`)**：
          * `^`: 文字列の始まり
          * `[a-zA-Z0-9.!#$%&'*+/=?^_`{|}\~-]+` :  `@\` の前の部分（ユーザー名など）で使える文字（アルファベット、数字、特定の記号）を1文字以上
          * `@`: アットマーク
          * `(?:example.com|yourcompany.co.jp)`: `example.com` または `yourcompany.co.jp` のいずれか
              * `|` は「または」を意味します。複数のドメインを許可したい場合は、`domain1|domain2|domain3` のように `|` で区切って列挙します。
          * `$`: 文字列の終わり
          * このパターンは、「`@`の前に何か文字があり、`@`の後に指定したドメインが来て、そこで終わる」という形式に厳密に合致するかをチェックします。
      * `MatchOptions.IgnoreCase`: ドメイン名の大文字・小文字を区別せずに照合します。（例: `Example.com` でも `example.com` と同じとみなす）
      * このチェックは、`IsBlank` のチェックが `false`（つまり何か入力されている）だった場合にのみ実行されます。

3.  **`Notify()` メッセージの使い分け:**

      * `IsBlank` の条件で「メールアドレスを入力してください。」
      * `!IsMatch` の条件で「有効なメールアドレス（...ドメイン）を入力してください。」
      * このように条件を分けることで、ユーザーに具体的なエラー内容を伝えられます。

### SharePoint/Listsへの格納

  * `EmailAddress: TextInput_Email.Text`
      * SharePoint/Lists に、メールアドレスを保存するための「**EmailAddress**」のような列（単一行テキスト型が適切です）を作成しておけば、そこに値を格納できます。

この方法で、メールアドレスの入力チェックと、指定ドメインの固定化、そしてメッセージの区別が実現できます。試してみてください！
